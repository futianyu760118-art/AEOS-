# AEOS M10 POMS V2.1 架构对齐方案（待 G0 评审）
日期：2026-10-10。状态：PROPOSED，不替代已签批的 AEOS V7.2 总纲。
## 目的
POMS 是末端岗位自适应工作入口，不是独立 ERP 或第二公共 Kernel。坚持标准化、自动化、智能化与精益约束；三化正式释义待业务 Owner 对总纲核验。
## 归属红线
- M01：身份/组织/岗位权限、Goal/Decision/Action、Guard、共享 Agent/Skill/Memory。POMS 只读取并调用，不重建事实源。
- M02：统一 Object/Event/Evidence/Audit/Provenance/Value Ledger；POMS 不形成第二证据和主数据中心。
- M03/M03A：管理者 Result/Exception/Decision 视图，不接管专业事实。
- M04～M09：专业业务主数据、规则、算法和 Result；POMS 通过 Domain API/Facade 调用。
- M10：岗位功能装配、UI schema 渲染、移动执行界面、采集交互、待办反馈及离线队列；本地仅维护会话/暂存/同步状态。
- M11：API/事件/设备连接与协议适配；LLM 不直接控制设备，联锁留在设备/PLC。
- M12：合同测试、CI、门禁、日志和可观测性。
- DEH 是 M01+M02 的跨域逻辑链，不新增一级模块，Action/Result 验证语义以 contracts/DEH_CONTRACT_V1.md 为准。
## 公专分离
公共：M01/M02/M11 能力及可复用的 M10 页面渲染器、扫码拍照语音输入组件、任务卡和待办/结果视图。
专业：专业中心中的订单、生产、质量、财经等领域能力。
企业配置：tenant/org/role/审批/流程/接口映射。
产品专用包：product schema/工艺/检验/Skill/UI schema/设备 adapter，须独立版本及租户隔离。
标准业务能力包是专业中心 API 的“界面能力描述/适配”，不复制专业算法及事实数据。
## 岗位装配
身份认证 -> M01 解析组织岗位及 Policy -> 匹配域能力、企业配置和产品版本 -> 过滤设备能力/权限 -> 生成 UI manifest -> 行动实时校验。
兼岗仅合并可见功能；写入/审批必须逐次校验最小权限与职责分离。
## 手机界面
首页默认未来待办、过去结果、异常；扫码、拍照、语音、离线暂存和 AI 辅助按权限装配。目标为常用操作尽量三步完成；不把模拟完成当已验证。
## 末端输入
现场 -> M10 带来源采集 -> 所属专业中心人机审核 -> M02 清洗/标准化/去重/多维分类 -> 授权管理流程人机复核 -> 受控归档/可信发布；根据数据级别允许带“待审核”标识的实时业务流转。原始事实保留，修订走版本，不能静默覆盖。
## 状态语义
Action done 仅代表执行者声明完成；Result submitted -> verified/rejected，验证权限与 Guard 由 M01 管理；Evidence 关联 M02。不得另建状态机。
## 迁移验收
恒剑灯具 -> 贞观定时器：公共仓代码无改动；更换 tenant 配置和产品专用包；验证多产品并存、API schema、权限隔离、幂等、证据链、设备联锁、回滚。技术迁移通过不等于 G6 商业复制达标。
## 门禁
L0 模拟验证依赖 G0；L1 MVP 依赖 G1/G2/G3；L2 推广关注 G4；L3 跨企业复制满足 G6（含 T0/Value）；L4 自治深化须 G5。任何 DONE 必须按 ledger 门禁证明。
